## Confirmed cause

The fetch field is correctly named `html` and contains 1,988,895 characters of
the requested thread page. It has no static application/ld+json script. The
saved renderer creates its QAPage markup later in the browser. The old parser
only read static QAPage markup, so it reported no_verified_plain_original_post
despite original source text being present. This is a collection parser defect,
not a relevance decision, model failure or evidence that the thread is empty.

The saved public `thread_view` bootstrap has the original thread at index 1,
its title at `[1][8]` and its plain body at `[1][12]`. The renderer's FU/QJ
accessors corroborate those fields. Thread identity at `[1][0][0]` and the
canonical link both match 106429666. Original publication microseconds are at
`[1][0][1]`, as corroborated by the renderer's Pi accessor; the resulting date
is 2021-04-16T15:27:49.885Z. The later modified timestamp is not substituted.
The original author's public profile is at `[3]`; its user ID matches
`[1][6]`. That ID is an author ID, not a reply or message ID.

## Small correction implemented

`n8n/extract-original-post-v2.js` is replacement code for the existing
**Extract original post** node. The workflow builder reads that same file.
The existing prepared workflow JSON and original tagging workflow are kept.
Parser v2 is a collection parser revision, unrelated to model extract/v2.

The static QAPage branch remains supported. For a page without that markup,
the parser decodes only one supported single-quoted thread_view JSON literal.
It handles quoted characters, hex/Unicode escapes and escaped JSON backslashes
as data, then uses JSON.parse. It never evaluates page code or executes page
scripts. It requires the thread page marker, supported field shape, exact
thread identity and a matching canonical link. Unsupported, ambiguous,
identity-mismatched, blank or HTML-valued bodies fail closed with a retained
failure reason. It never substitutes replies, page boilerplate or a summary.
Original text is copied without trimming or HTML conversion. Replies remain
unfetched and replies_complete remains false. Existing request budgets,
credentials, no-retry settings, privacy and import guards are unchanged.
